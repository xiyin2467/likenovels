# 竞品分析 + 产品规划 — 设计文档

- 日期：2026-06-08
- 子项目：海外小说类 App 的第一个子项目（竞品分析 + 产品规划）
- 状态：已确认设计，待用户复核 spec

## 1. 背景与目标

工作区已有两个竞品 APK：

- `竞品分析/竞品apk/GoodNovel_v2.5.8.1168.apk`
- `竞品分析/竞品apk/iReader_international_v8.7.3.1.apk`

目标：在动手做自己的海外小说 App 之前，先对两款竞品做**产品 + 技术**双维度的详尽拆解，并据此产出一套**产品规划**文档（含市场/定位建议）。本子项目只交付分析与规划文档，不写 App 代码。界面设计（impeccable）与实际开发放到后续独立子项目。

### 成功标准

- 两款竞品各有一份「技术拆解」+「产品分析」，事实可溯源（保留 androguard 原始提取数据）。
- 一份竞品横向对比文档，给出明确结论。
- 一套产品规划文档：基于竞品事实反推目标市场建议、功能清单（MoSCoW 分级）、MVP 范围与路线图、变现模型、技术选型建议。
- 所有文档中文 + Markdown。

## 2. 范围

### 包含

- 用 androguard（已确认安装）对两个 APK 做静态分析。
- 产品层面的功能地图、用户流程、变现、增长玩法、UX 亮点/短板分析。
- 基于分析的产品规划与市场建议。

### 不包含（后续子项目）

- App 的高保真界面设计与前端实现。
- 后端架构落地、真实代码脚手架。
- 动态分析（运行 APK、抓包）——本机无 Android 运行环境，仅做静态分析。

## 3. 工具与可行性

- 本机可用：`python`、`androguard`（已安装）、`unzip`、`tar`。
- 本机缺失：`java`、`jadx`、`apktool`、`aapt`。因此采用纯 Python（androguard）路线做静态拆解：解析 AndroidManifest、权限、四大组件、DEX 中的类/字符串以推断集成的 SDK、`resources.arsc` 中的语言/地区配置、签名证书。
- 限制：无法运行 App，故用户流程与体验分析基于静态信息 + 产品认知推断，会在文档中标注「推断」与「事实」区分。

## 5. 分析维度

### 技术拆解（每个 APK）

- 应用基本信息：包名、版本号/版本名、minSDK/targetSDK/compileSDK。
- 权限清单（并按用途归类：网络/存储/通知/广告标识等）。
- 四大组件清单：Activity / Service / BroadcastReceiver / ContentProvider（用于推断页面与后台能力）。
- 集成的第三方 SDK：广告（AdMob、Facebook、AppLovin 等）、支付（Google Play Billing、第三方）、统计与归因（Firebase、Adjust、AppsFlyer 等）、推送、崩溃监控、登录（Google/Facebook）。
- 国际化：支持的语言/地区列表（来自资源配置）。
- 签名证书信息（发行主体线索）。

### 产品分析（每个 APK）

- 功能地图（基于组件名 + 资源 + 产品认知）。
- 核心用户流程：注册/登录 → 内容发现 → 阅读 → 付费解锁。
- 内容与变现模式：金币、订阅、章节解锁、广告。
- 增长玩法：签到、任务、邀请、推荐位、推送。
- UI/UX 亮点与短板。

## 6. 产品规划内容

- 市场与定位建议：欧美英语 vs 东南亚 vs 多区域多语言，给理由与取舍。
- 产品功能规划：功能清单 + MoSCoW（Must/Should/Could/Won't）。
- MVP 范围与路线图：第一版做什么、后续迭代节奏。
- 变现模型：金币/订阅/解锁/广告的组合设计。
- 技术选型建议：客户端、后端、内容与本地化方案。

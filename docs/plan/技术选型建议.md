# 技术选型建议

> 原则：出海合规优先、复用 GoodNovel 验证过的栈、避免国内渠道方案、为多语言/多平台预留扩展。

## 1. 客户端

### 推荐：跨平台框架优先（Flutter）

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| Flutter | 一套码 iOS/Android、UI 表现力强、阅读器可高度定制、开发效率高 | 阅读器分页/排版需自研或用 epub 渲染库 | **推荐**：小团队出海首选 |
| React Native | 生态大、JS 人才多 | 复杂阅读器性能/排版较吃力 | 备选 |
| 原生 Android+iOS | 性能/体验最佳 | 双端成本翻倍 | 资源充足或体验极致诉求时选 |

> 说明：GoodNovel 为原生（资源充足）；iReader 阅读内核为原生 + C/C++（`libmobi`）。我们作为新团队，**Flutter 一套码双端**更利于快速验证；阅读器排版可用社区 epub/分页方案起步，后续按需原生优化。

### 阅读器实现要点
- 章节内容建议存为结构化文本/轻量 HTML，客户端做分页与排版（字号/行距/主题实时重排）。
- 本地缓存已解锁章节（加密存储），离线可读。
- 进度同步：本地 + 云端双写。

## 2. 后端

| 层 | 建议 | 说明 |
|---|---|---|
| 语言/框架 | Go 或 Node.js(NestJS) / Java(Spring Boot) | 按团队栈选；Go 性能与部署轻量 |
| 架构 | 模块化单体起步，按域拆分 | YAGNI，避免一上来上微服务 |
| 核心域 | 账号、内容(书/章)、计费/钱包、解锁、广告回调、推送、运营位 | 清晰边界 |
| 数据库 | PostgreSQL（主）+ Redis（缓存/计数/排行榜） | 关系数据 + 高频读 |
| 对象存储 | S3 兼容（封面、章节文件、字体） | CDN 加速 |
| 搜索 | 初期 PG 全文/Meilisearch，规模后 Elasticsearch | 渐进 |

## 3. 内容管理（CMS）

- 自建轻量后台：书籍/章节录入、免费章数、解锁定价、上下架、运营位/榜单配置。
- 支持批量导入（翻译/采购内容管线对接）。

## 4. 海外三方服务栈（对标 GoodNovel，避开国内方案）

| 能力 | 选型 | 备注 |
|---|---|---|
| 推送 | Firebase Cloud Messaging (FCM) | 唯一推送通道，合规 |
| 内购 | Google Play Billing（+ App Store IAP for iOS） | 数字内容强制 |
| 广告聚合 | AppLovin MAX | 聚合 AdMob/Unity/ironSource/Mintegral/Vungle |
| 归因 | AppsFlyer 或 Adjust（择一） | 买量 ROI 核算 |
| 行为埋点 | 自建事件 + 第三方（如 Amplitude / 神策海外版） | AB 与漏斗分析 |
| 崩溃/性能 | Firebase Crashlytics + Sentry | 稳定性 |
| 登录 | Google / Facebook / Apple Sign-In | 海外主流 |
| 同意管理 | Google UMP / 第三方 CMP | GDPR/CCPA |

## 5. 合规与安全

- targetSdk 取上架要求的最新版本；权限**最小化**（仅 INTERNET/通知/必要存储）。
- 不使用：悬浮窗、MANAGE_EXTERNAL_STORAGE、应用内安装 APK、自启动、日历提醒等高风险权限（iReader 反面教材）。
- 已解锁内容本地加密；账号注销与数据删除入口（Google Play 政策）。
- 客户端可做基础加固/混淆，但避免国内加固壳（海外分发与上架风险）。

## 6. 基础设施与交付

- 部署：海外云（AWS/GCP）+ CDN（CloudFront/Cloudflare），就近覆盖目标市场。
- CI/CD：自动构建双端包、灰度发布。
- 多语言：i18n 文案资源化（key-value + 翻译平台），架构层支持从第一天起。

## 7. 第二阶段技术储备（暂不实现）

- 有声/TTS（云端 TTS 或端侧）、漫画阅读器、社区/UGC、推荐系统（召回+排序）。

## 8. APK 深度映射后的架构补充

### 8.1 Flutter 客户端分包

建议采用 feature-first 结构，直接对应竞品 APK 映射出的业务域：

```text
lib/
├─ app/              # AppShell、路由、全局 Tab、主题、多语言
├─ core/             # 网络、存储、错误、权限、SDK facade
├─ features/
│  ├─ discover/      # 首页、推荐流、分类、榜单、搜索
│  ├─ book/          # 书籍详情、章节列表、书评、相似推荐
│  ├─ reader/        # 阅读器、目录、进度、主题、缓存、书签
│  ├─ wallet/        # 钱包、充值、流水、广告奖励、等待解锁
│  ├─ account/       # 登录、个人中心、语言、隐私、注销
│  ├─ growth/        # FCM、站内信、签到、活动
│  └─ analytics/     # 事件定义、埋点、实验参数
└─ shared/           # 通用组件、模型、工具
```

### 8.2 后端模块化单体边界

首版不要拆微服务，但必须按模块建边界：

- `identity`：游客、邮箱、Google/Apple/Facebook、注销。
- `content`：书、章节、作者、分类、标签。
- `discovery`：首页运营位、榜单、推荐流、搜索。
- `reader`：书架、进度、书签、阅读历史。
- `entitlement`：免费章、已解锁章、等待解锁、广告解锁资格。
- `wallet`：余额、流水、奖励币、消费账。
- `payment`：Google Billing/App Store IAP 验单与回调。
- `ads`：激励广告回调、防作弊、奖励发放。
- `growth`：FCM、站内信、签到、活动配置。
- `analytics`：事件接收、漏斗、实验参数。
- `admin`：CMS 后台接口。

### 8.3 SDK 接入顺序

1. Firebase Crashlytics / Analytics：开发早期接入，先解决稳定性和基础事件。
2. Google Play Billing / App Store IAP：付费闭环前接入。
3. FCM / APNs：追更、等待解锁和召回。
4. AppLovin MAX：激励广告解锁，首版只做 Rewarded。
5. AppsFlyer 或 Adjust：买量前接入，避免上线后补归因。
6. CMP / Google UMP：欧洲上线前完成同意管理。
7. Remote Config / AB：增长阶段再做价格、广告频次、等待时长实验。

### 8.4 明确禁区

不接入 iReader 国内版暴露出的以下能力：支付宝/微信/QQ 钱包、穿山甲/快手/广点通/百度等国内广告、厂商推送全家桶、应用内安装 APK、悬浮窗、全盘存储、日历读写、自启动、国内加固壳、插件化下载执行。

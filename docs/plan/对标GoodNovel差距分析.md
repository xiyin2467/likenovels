# 对标 GoodNovel 差距分析

> 依据：`docs/research/GoodNovel/*`、`docs/research/_raw/goodnovel.json`、当前 `docs/plan/*` 与 `prototypes/v0-lofi/*`。
> 目的：判断 likenovel 现状离 GoodNovel 已验证的出海网文打法还差什么，并给出补齐优先级。

## 1. 一句话结论

likenovel 的强项是"想清楚了"（竞品拆解、定位、MoSCoW、MVP 路线、变现模型、APK 架构映射、模块边界齐全）；短板是"还没做出来"：原型只覆盖变现链路中段，GoodNovel 真正赚钱的两头（冷启动转化 + 留存养成）基本为空；同时内容供给、埋点字典、API 契约、真实定价验证尚未落地。

## 2. 现状盘点

### 已具备
- 竞品分析：GoodNovel/iReader 技术拆解 + 产品分析 + 横向对比 + APK 深度架构映射。
- 规划：市场与定位、产品功能 MoSCoW、MVP 范围与路线图、变现模型、技术选型、App 架构分配。
- 原型：App Shell（Discover/Library/Wallet/Me）+ 详情 + 阅读器 + 付费墙 + 充值 + 部分二级页。

### 尚未具备
- 冷启动与账号流、留存养成实体化、内容供给、埋点字典、API/数据模型、生产代码、内容分级合规。

## 3. 分层差距

### 3.1 原型/产品设计层

| 能力 | GoodNovel | likenovel 原型 | 判断 |
|---|---|---|---|
| Splash + Guide 冷启动引导 | 有（性别/口味选择） | 无 | MVP 关键缺口，影响冷启动推荐与首屏转化 |
| 登录/注册/游客流 | Email/Google/Facebook | 无，Me 页直接已登录态 | MVP 关键缺口 |
| 等待解锁养成（倒计时列表/回访钩子） | `WaitUnlockListActivity` | 仅付费墙一行倒计时文字 | 留存核心机制未做实 |
| 解锁/充值/广告结果反馈态 | 有 | 仅 toast | 转化关键节点体验缺失 |
| 搜索（建议/历史/筛选） | 有 | 仅跳转骨架页 | 半成品 |
| 详情深度（作者页/系列/相似推荐） | 有 | 仅基础详情+书评入口 | 部分缺 |
| 首充礼包/新人赠币 | 推断有 | 变现文档提及，原型无 UI | 缺（高 ROI） |

### 3.2 规划/分析层

- **内容供给方案**：MVP 路线图自标"决定成败的前置依赖"，但无首批书源、翻译/签约/采购管线方案。最大空白。
- **埋点事件字典**：架构文档有事件名，但缺参数定义、触发时机、漏斗口径，无法直接交付工程。
- **后端 API 契约 + 数据模型**：仅到模块边界，缺接口定义与表结构。
- **真实运营参数全为推断**：免费章数、解锁单价、等待时长、广告频次、付费墙位置未做 data.ai/Sensor Tower 或实机验证。

### 3.3 工程落地层

- **0 行生产代码**：当前是原型 HTML + Markdown，Flutter 客户端、后端模块化单体、最小 CMS 均未起脚手架。
- **i18n 实际方案**：文案 key 管理、翻译流程未落地。

### 3.4 合规层

- **内容分级/年龄门**：女频网文含成人向内容，双端商店均要求年龄分级与内容提示，规划未覆盖。
- CMP、账号注销目前仅骨架页，无真实流程。

## 4. 主动延后（无需现在补）

漫画、有声/TTS/AI 朗读、社区/发帖、作者 UGC 中心、Gems 二级货币、批量订购——GoodNovel 有但我们主动延后，符合 YAGNI，判断正确。

## 5. 补齐优先级

按对跑通 MVP 闭环的影响排序：

1. **内容供给方案**（非工程，但卡住一切）→ `docs/plan/内容供给方案.md`
2. **冷启动 + 账号流**（原型最大缺口，影响所有转化数据）→ 原型新增 Splash/Guide/Login/游客
3. **埋点字典 + API 契约**（让规划能交付工程）→ `docs/plan/埋点事件字典.md`、`docs/plan/后端API与数据模型.md`
4. **真实定价验证**（实机/三方数据）→ 后续动态验证任务
5. **内容分级合规**（上架前必须）→ 并入合规清单

## 6. 数据可信度与缺口

- 本分析基于 APK 静态拆解与产品认知，未做动态运行/抓包。
- GoodNovel 的运营细节（定价、解锁节奏、广告频次、付费墙位置、首充设计）均为推断，落地前需实机或三方数据验证。

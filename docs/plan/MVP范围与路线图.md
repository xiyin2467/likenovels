# MVP 范围与路线图

> 取自《产品功能规划.md》的 Must 项。原则：用最小功能集跑通「内容 → 阅读 → 解锁 → 充值」闭环并验证买量 ROI。

## 1. MVP 目标

**一句话**：英语市场上线一款网文 App，用户可免登录试读，触达付费墙后优先订阅 VIP 全场畅读；非会员可用金币按章解锁，余额不足时进入充值页。

**验证假设**：
- 内容与阅读体验能否撑起 D1/D7 留存。
- 订阅优先 + 非会员金币兜底的变现闭环是否成立。
- 买量 ROI（LTV/CPI）是否有正向苗头。

## 2. MVP 功能清单（仅 Must）

- 账号：游客模式、邮箱、Google 登录、账号注销。
- 书库：书城首页、分类、榜单、搜索、书籍详情。
- 阅读器：翻页/滚动、字号/字体/行距、日间/夜间/护眼主题、目录、进度记忆与同步。
- 变现：免费试读 + 付费墙、VIP 订阅全场畅读、非会员单章金币解锁、金币充值（Google Billing）、钱包/消费记录。
- 增长基建：FCM 推送、AppsFlyer 或 Adjust 归因、行为埋点。
- 合规：多语言架构（先英语）、隐私政策/条款、GDPR 同意管理（CMP）。
- 内容后台：最小化 CMS（上传书籍/章节、设置免费章数与解锁价格）。

## 3. 明确不在 MVP（避免过度设计）

漫画、有声/TTS、社区/发帖、作者 UGC 中心、邀请裂变、赛事、批量订购、个性化推荐（先用榜单/编辑位代替）。等待解锁与付费墙广告解锁不进当前 MVP。

## 4. 里程碑路线图

### V0.1 — 内核闭环（MVP 内部可用）
- 内容后台能上书上章；客户端能登录、找书、读书、解锁、充值。
- 埋点/归因接入，关键事件可追踪。
- 验收：一本书可完整走通"试读→付费墙→解锁→充值"。

### V1.0 — 英语首发（公开上线）
- 接入钱包 Watch & earn 激励广告；等待解锁视数据放入后续版本。
- 推送召回、签到/每日免费金币（Should，视进度）。
- 合规闭环（CMP、注销、政策页）通过 Google Play 审核。
- 验收：上架 Google Play，跑通买量 → 留存 → 付费数据看板。

### V1.x — 留存与转化优化（数据驱动）
- 个性化推荐、批量订购、自动解锁、站内信、签到任务体系。
- AB 测试付费墙位置、解锁定价、等待时长、广告频次。

### V2.0 — 增长扩张
- 扩西班牙语 + 葡萄牙语（拉美），多币种计费。
- 视情况引入书评互动与更多本地化市场。

### V3.0 — 内容生态（验证后投入）
- 有声/TTS、漫画、社区、作者 UGC 中心，构建内容供给护城河。

## 5. 关键前置依赖（非工程，但决定成败）

- **内容供给方案**：MVP 前必须确定首批书源（采购/翻译/签约），建议先备 50–100 本可读完整作品 + 持续更新管线。
- **买量预算与素材**：上线即需投放预算与素材产能。
- **支付与开发者账号**：Google Play 开发者账号、商品配置、税务主体（如新加坡/香港主体）。

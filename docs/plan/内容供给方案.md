# 内容供给方案

> 依据：`docs/plan/MVP范围与路线图.md` 标注的"决定成败的前置依赖"、`docs/research/GoodNovel/产品分析.md`。
> 目的：解决 likenovel 最大空白——MVP 上线前的首批书源、版权、翻译与持续更新管线。

## 1. 为什么内容是第一优先级

GoodNovel 的变现闭环依赖"读者愿意一直追更"。没有足量、可追更、品类对路的内容，再好的付费墙和广告也无处施展。内容供给决定 D1/D7 留存与付费率，比任何功能都更早卡住 MVP。

## 2. 内容目标（MVP）

| 指标 | MVP 目标 | 说明 |
|---|---|---|
| 首发完本书数 | 50–100 本 | 保证新用户找到可一次性读完的作品 |
| 连载在更书数 | 10–20 本 | 制造追更与等待解锁回访 |
| 单本章节量 | ≥ 60 章 | 支撑解锁漏斗有足够付费章 |
| 首发品类 | 女频为主：狼人/霸总/重生/吸血鬼/罗曼奇幻 | 对标 GoodNovel 高转化品类 |
| 更新频率 | 在更书每周 ≥ 5 章 | 维持追更钩子 |

## 3. 书源获取路径（按性价比排序）

| 路径 | 说明 | 成本/风险 | 优先级 |
|---|---|---|---|
| 签约英文原创作者 | 直接签约海外网文作者，平台分成 | 起量慢，但版权干净、可独家 | 高（长期护城河） |
| 采购已完结英文网文版权 | 向版权方/中小平台批量采购完本 | 一次性成本，可快速铺量 | 高（解决首发量） |
| 中文网文翻译出海 | 采购中文女频版权 + 翻译 | 翻译成本高、周期长、需质控 | 中（差异化但重） |
| AI 辅助翻译 + 人工润色 | 降低翻译成本，人工把关质量 | 质量风险，需建审校流程 | 中（管线优化项） |
| UGC 作者投稿 | 开放作者中心吸引投稿 | 第二阶段能力，MVP 不做 | 低（V3.0） |

> MVP 组合建议：**采购完本铺量（首发 50–100 本）+ 签约少量独家在更书（10–20 本）**，翻译路径在验证留存后再投入。

## 4. 版权与合规

- 每本书必须有可追溯的版权授权链（授权方、授权范围、地域、期限、分成）。
- 明确授权地域是否覆盖首发市场（英语欧美）及后续扩张地（拉美/东南亚）。
- 翻译作品需同时持有原作版权方的翻译与信息网络传播授权。
- 建立版权台账，记录每本书的授权状态与到期提醒。

## 5. 内容生产管线

```mermaid
flowchart LR
  Source["书源采购/签约"] --> Ingest["导入 CMS"]
  Ingest --> QC["质量审校"]
  QC --> Grade["内容分级/标签"]
  Grade --> Schedule["排期与免费章设置"]
  Schedule --> Publish["上架/连载更新"]
  Publish --> Monitor["数据监控"]
  Monitor --> Schedule
```

### 各环节要点
- **导入 CMS**：支持批量导入（章节切分、封面、简介、品类、标签）。
- **质量审校**：检查翻译/排版/敏感内容；建立审校 checklist。
- **内容分级/标签**：标注年龄分级（是否成人向）、品类、热门 trope，供推荐与商店合规使用。
- **排期与免费章设置**：每本设免费章数（前 3–10 章）、解锁单价、等待解锁时长。
- **连载更新**：在更书按周排期更新，配合推送召回。
- **数据监控**：按书看读完率、解锁率、付费贡献，淘汰低效内容、加推高效内容。

## 6. 内容运营指标

- 单书读完率、章均流失点、付费墙到达率。
- 单书解锁率（付费/广告/等待各占比）、单书 ARPU。
- 在更书追更留存（更新日回访率）。
- 品类维度的留存与付费对比，指导后续采购方向。

## 7. 关键前置 checklist（MVP 上线前必须完成）

- [ ] 确定首发品类与目标书单（含完本+在更配比）。
- [ ] 锁定首批 50–100 本书源及版权授权。
- [ ] 搭建最小 CMS（批量导入 + 免费章/定价/分级设置）。
- [ ] 建立审校与分级流程及 checklist。
- [ ] 确定在更书更新排期与责任人。
- [ ] 建立版权台账与到期提醒机制。

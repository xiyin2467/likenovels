# iReader（"国际版"）产品分析

> 基于 APK 静态结构（`docs/research/_raw/ireader.json`）+ 阅读类产品认知。
> 重要前提：该包实为掌阅**国内版**（`com.chaozh.iReaderFree` / `com.zhangyue.iReader`），见《技术拆解》关键发现。本文据此分析其产品形态，并作为出海的**反面/借鉴参照**。

## 1. 产品定位

掌阅 iReader 是中国头部的**综合数字阅读平台**，强项是**专业级阅读体验**与**内容形态广度**：网文、出版书、漫画、PDF/文档、有声/TTS、AI 朗读一应俱全，面向泛阅读人群（含付费出版书与免费网文）。

与 GoodNovel 相比：GoodNovel 是"出海网文 + 短故事变现"打法；iReader 是"全品类阅读器 + 国内重运营"打法。

## 2. 功能地图（按用户视角）

- **账号**：微信/QQ/微博/抖音三方登录、一键登录、账号安全、体验/会员。
- **书架**：书架管理、封面更新、备份、云同步、最近阅读。
- **发现**：搜索、书单（创建/频道/搜索）、订阅、活动（EventActivity）、投放推荐（ToufangRecommend）。
- **阅读（核心）**：TXT/HTML(EPUB)/PDF/Story/漫画 多格式阅读器；笔记、云笔记、书摘、字体、皮肤、护眼、休息提醒、阅读进度样式。
- **听书/AI**：TTS 朗读、AI 电台、AI 朗读、AI BookBoy 助手、俱乐部播放器。
- **付费**：在线计费（Fee/ReFee）、自动购买、代金券（看激励视频得券）。
- **工具**：扫码、WiFi 传书、应用锁、网络诊断、本地图片/文档。
- **设置**：消息通知、隐私、个性化、SDK 启动管理、自动购买等。

## 3. 核心用户流程（推断）

1. **启动**：Welcome → 书架（老用户）或选书引导（新用户 `SelectBookOldActivity`/`UpdateUserGuideActivity`）。
2. **阅读漏斗**：书城/书单/搜索 → 书籍 → 阅读器；付费书触达计费页（`ActivityFee`），可自动购买或看激励视频得代金券抵扣。
3. **听书场景**：文字转 TTS/AI 电台，覆盖通勤/睡前等无屏场景。
4. **召回**：全厂商推送 + 日历提醒 + 角标，强力拉活（国内打法）。

## 4. 变现模式（事实支撑 + 推断）

- **付费阅读/书币**（事实：`ActivityFee`/`ActivityReFee`/`ActivitySettingAutoBuy`）：按书/章付费，支持自动购买；支付走支付宝/微信/QQ。
- **激励广告抵扣**（事实：`VoucherRewardVideoActivity` + 多家广告聚合）：看广告得代金券解锁，免费用户变现。
- **会员/订阅**（推断：`SubscribeDetailActivity`/`SubscribeService`/体验会员）：包月畅读类权益。
- **广告位**（事实：穿山甲/快手/广点通/百度等）：信息流/插屏/激励多形态广告。

## 5. 体验亮点

- **阅读内核专业**：多格式（含 PDF/EPUB）、排版/字体/皮肤/护眼/笔记/云同步，体验深度行业领先。
- **内容形态最全**：文字 + 出版书 + 漫画 + 文档 + 有声 + AI 朗读。
- **AI 能力**：AI 电台、AI 朗读、AI 助手，已落地到产品。
- **场景覆盖广**：阅读 + 听书 + 工具（传书/扫码/应用锁）。

## 6. 潜在短板（针对出海视角，推断）

- **不可直接出海**：国内渠道 SDK、厂商推送、支付宝/微信支付、加固壳，均不适配 Google Play 海外环境。
- **权限激进**：MANAGE_EXTERNAL_STORAGE、悬浮窗、应用内安装、日历、自启动等违反 Google Play 政策。
- **包体重、SDK 多**：300 Activity / 60 Service / 7 DEX，工程复杂度高，启动与隐私合规负担大。
- **targetSdk 30 偏旧**：海外上架需 target 至新版本。

## 7. 对我们的启示（要点）

1. **阅读内核值得学**：排版、字体、皮肤、护眼、进度、笔记、TTS 是阅读 App 的体验底盘，做出海产品也要把"阅读器"打磨到位。
2. **听书/TTS 与 AI 朗读**是差异化方向，但属第二阶段能力（YAGNI，MVP 不做）。
3. **反面教材**：国内"全厂商推送 + 激进权限 + 加固"那套**不能照搬到海外**，海外要走 FCM + 合规权限 + Google Billing。
4. **多形态内容（漫画/出版/文档）会显著增加复杂度**，出海初期应聚焦网文单形态跑通闭环。
5. 内容广度 ≠ 增长效率；出海更应学 GoodNovel 的"窄而深的变现闭环 + 强本地化 + 买量归因基建"。

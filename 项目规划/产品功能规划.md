# 产品功能规划（MoSCoW）

> 功能来源：对标 GoodNovel（出海标杆）+ 借鉴 iReader 阅读内核。
> 优先级：**Must**=MVP 必须；**Should**=尽快补齐；**Could**=锦上添花；**Won't（本期不做）**=明确不做。

## 模块 1：账号体系

| 功能 | 优先级 | 对标来源 | 说明 |
|---|---|---|---|
| 游客模式（免登录可读） | Must | GoodNovel | 降低启动门槛，先体验后注册 |
| 邮箱注册/登录 | Must | GoodNovel EmailLogin | 基础账号 |
| Google 登录 | Must | GoodNovel | 海外主流三方登录 |
| Facebook 登录 | Should | GoodNovel | 提升转化 |
| Apple 登录 | Should | iOS 上架要求 | 上 iOS 时为必须 |
| 个人资料编辑 | Should | EditProfile | 头像/昵称 |
| 多设备书架同步 | Should | iReader SyncService | 账号绑定后云同步 |

## 设计原则

- **MVP 只做 Must**：账号最小集 + 书库发现 + 阅读器 + 金币解锁/等待解锁/激励广告/充值 + 推送/归因/埋点 + 合规。
- **Should 在 MVP 后 1–2 个迭代补齐**。
- **Won't 项（社区/UGC/TTS/漫画/有声）明确本期不做**，避免过早复杂化（YAGNI）。
